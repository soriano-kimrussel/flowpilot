# Testing

## Suites

| Suite           | Command                    | Needs credentials?                                                                                       | Covers                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| --------------- | -------------------------- | -------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Unit            | `npm test`                 | No                                                                                                       | Definition validation, every action handler, conditions and templates, executor state transitions, branching, failures, limits, cancellation, transient retries, idempotent replay on retry, duplicate detection, AI demo determinism, invalid/timeout/rate-limited provider output and fallback, data minimization, redaction, CSV injection, webhook credential/request validation, permissions, metrics, webhook route + manual-run route authorization (mocked session)                                        |
| Local database  | `npm run test:db`          | No                                                                                                       | All migrations applied to real Postgres (PGlite) with a Supabase auth/roles shim: signup bootstrap, cross-workspace isolation (read/insert/update/delete/move), anon denial, role rules (member vs admin vs owner), column grants, notification privacy, versioning, definition shape constraint, lead triggers + loop guard, job claiming, execution idempotency + immutability, side-effect unique index, webhook ingest (auth, required fields, dedupe, rate limit), demo seed/clear, scoped metrics, templates |
| Hosted Supabase | `npm run test:integration` | `TEST_SUPABASE_URL`, `TEST_SUPABASE_PUBLISHABLE_KEY`, `TEST_SUPABASE_SECRET_KEY` (**test project only**) | RLS through the real PostgREST API and Auth; skipped otherwise                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| E2E public      | `npm run test:e2e`         | No (needs `npx playwright install chromium` once)                                                        | Landing/features/pricing/privacy render, login + registration client validation                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| E2E core flow   | `npm run test:e2e`         | App running against a Supabase test project + `E2E_EMAIL`/`E2E_PASSWORD` or `E2E_REGISTER=1`             | Login/registration, lead creation, workflow from template, manual run, persisted step results after reload, simulated email, logout                                                                                                                                                                                                                                                                                                                                                                                |

The PGlite suite emulates Supabase’s `auth.uid()`, roles and default grants; it does not emulate PostgREST or GoTrue. The hosted suite and the E2E core flow cover those.
